# Single-channel occipital EEG for a password selection BCI based on steady-state visual evoked potentials (SSVEP)

## Required components and downloads

* **EXG Pill by Upside Down Labs**. An instrumentation amplifier designed for recording small biopotential signals such as EEG, EMG, and ECG.

* **2x Arduino / Raspberry Pi / compatible microcontroller board**. One board is used to acquire the analog EEG signal from the EXG Pill and transmit the data to the computer. The second board is used to control the LEDs that generate the flickering visual stimuli.

* **PsychoPy**. Used as the central software environment for the entire SSVEP BCI. It generates the frame-locked visual stimuli, controls the calibration procedure, acquires EEG data through the serial connection, records stimulus and experimental markers, and runs the real-time BCI interface. It is used because it provides precise synchronization with the monitor refresh cycle while also allowing everything else to be handled within a single program.

## Electrode placement

Initial electrode placement followed the international 10–20 system, with the recording electrode positioned at **O1 or O2** over the occipital region, where visual processing predominantly occurs. The approximate electrode locations are shown in the figure below left (Malmivuo & Plonsey, 1995). The reference electrode was placed over the mastoid process behind the ear. This configuration produced good-quality SSVEP recordings and allowed different stimulation frequencies to be detected with 100% accuracy when each frequency was presented individually. However, classification performance decreased substantially when several flickering stimuli were displayed simultaneously. Several modifications to the visual stimulus were tested, including reducing the number of stimuli, increasing the distance between them, simplifying the screen layout, and comparing simultaneous stimulation with a more concentrated paradigm in which attention was directed toward one stimulus while the other stimuli continued flickering. Despite these modifications, classification accuracy did not exceed 50%.

Electrode placement was then reconsidered based on the reduced-channel SSVEP study by Kiser, Cantürk and Volosyak (2026). The authors report that when only a single EEG electrode is used, **Oz provides the highest classification accuracy**, followed by O1 and O2.  Based on these findings, the recording electrode in the present project was moved from O1/O2 to Oz, while the remaining two electrodes were positioned over the mastoid regions. **With this modified electrode configuration, the same SSVEP classification system that earlier scored below 50% achieved over 90% accuracy**. An additional limitation of the initial configuration was identified from the operating principle of the BioAmp EXG Pill. The amplifier performs a differential measurement between its IN+ (red) and IN− (black) electrodes, rather than measuring either electrode independently relative to the REF electrode. Therefore, when IN+ and IN− were positioned at O1 and O2, the recorded signal represented approximately the voltage difference O1 − O2. Since both O1 and O2  contain similar SSVEP activity, part of the response could have been attenuated through differential subtraction.

## Calibration stimulus generation and timing

Visual stimulation frequencies in approximately the 6–12 Hz range have been reported to produce relatively strong SSVEP responses, making this range suitable for an EEG system with a small number of recording channels (Hamidi Shishavan et al., 2024). However, SSVEP strength also varies between individuals. Therefore, candidate frequencies within this range that could be produced accurately on a 60 Hz monitor using an integer number of display frames per flicker cycle were tested experimentally. For me, the strongest and **most reliably distinguishable responses were obtained at 10 Hz and 12 Hz**, and these frequencies were therefore selected for the final two-target system. The visual stimuli are generated in PsychoPy, which allows stimulus changes to be synchronized with the refresh cycle of the monitor. A nominal 60 Hz display refreshes approximately once every 16.67 ms. Because a visual change can only occur when a new monitor frame is presented, an SSVEP frequency can be generated particularly reliably when one complete flicker cycle corresponds to an integer number of display frames. At exactly 60 Hz, the 10 Hz stimulus requires 6 frames per cycle because 60/6 = 10 Hz, while the 12 Hz stimulus requires 5 frames per cycle because 60/5 = 12 Hz.

The 10 Hz stimulus therefore follows a six-frame sequence consisting of **three white frames followed by three black frames**. Each complete cycle lasts approximately 100 ms. The 12 Hz stimulus follows a five-frame sequence consisting of **two white frames followed by three black frames**, giving a cycle duration of approximately 83.3 ms. A perfectly equal white–black duty cycle is not possible for 12 Hz because its five-frame cycle contains an odd number of frames; however, the repetition period, and therefore the fundamental stimulation frequency, remains 12 Hz. Before calibration begins, PsychoPy measures the actual full-screen refresh rate. After an initial warm-up period, frame intervals are measured over a series of screen refreshes and the median stable frame interval is used to calculate the actual refresh frequency. The program requires the measured refresh rate to fall between 58 and 62 Hz and terminates the experiment if more than 2% of the measured frames are substantially delayed. The actual stimulation frequencies are then calculated from the measured refresh rate. For every screen frame, the program uses a shared integer frame counter to determine the state of each stimulus.

The current frame number is divided modulo the number of frames in the corresponding flicker cycle. This determines whether the stimulus should be displayed as white or black during that particular monitor refresh. The program first draws the required state into the next display buffer and then calls `win.flip()`. With vertical-blank synchronization enabled, PsychoPy presents the prepared frame at the next monitor refresh. The final calibration uses **two simultaneously flickering targets**, rather than presenting the frequencies sequentially. The left target represents **NEXT and flickers at approximately 10 Hz**, while the right target represents **SELECT and flickers at approximately 12 Hz**. Before every trial, a yellow cue indicates which target the participant should attend to. Once stimulation begins, the cue disappears and **both targets flicker simultaneously**, while the **participant continues looking directly at the white fixation dot in the instructed target**. The classifier must identify which stimulus is being attended to while another frequency is simultaneously present.

Calibration consists of **30 trials: 15 NEXT trials and 15 SELECT trials**. Their order is randomized in balanced blocks. Each trial begins with a 0.75 s cue period, followed by **3.5 s of simultaneous flickering** and a 1 s REST period. The 3.5 s stimulation interval contains a 0.25 s initial settling period, a 3.0 s interval intended for EEG analysis, and a final 0.25 s guard period. This prevents the classifier from relying immediately on the transition into the stimulus and provides a consistent three-second SSVEP segment for subsequent analysis. Accurate timing of the visual stimulus was particularly important because earlier experiments performed in windowed mode produced measured frame intervals of approximately **20–28 ms**, rather than the approximately 16.67 ms expected from a stable 60 Hz display. **In windowed presentation, additional buffering and processing by the operating system's desktop compositor can influence when a prepared image actually becomes visible**. PsychoPy also specifically recommends true full-screen operation for experiments requiring accurate frame timing. Below you can see the stimuli that are generated for calibration.

Originally, visual stimulation and EEG acquisition were handled by different programs. This created a practical problem because opening the full-screen PsychoPy experiment interfered with the other applications involved in recording and caused the EEG connection to be lost. The final implementation therefore combines the experiment into one PsychoPy program. PsychoPy controls the visual stimulation and experimental sequence, while a separate acquisition thread inside the same program continuously reads the eight-channel CHORDS EEG stream from the Arduino through the serial connection. Stimulus timing and EEG timing use the **Python high-resolution clock**, based on `time.perf_counter()`. For visual events, the program does not simply record the time immediately before or after requesting a screen update. Instead, it uses PsychoPy's `callOnFlip()` mechanism to execute the timestamping function as part of the screen-flip operation. The timestamp of each important experimental event can therefore be associated much more closely with the frame on which that event was presented. The program **records the timing of individual display frames as well as markers for events such as CUE_ON, FLICKER_ON, FLICKER_OFF, RECORDING_START and RECORDING_END**.

EEG timing required a different approach because data arriving through USB serial communication are received in batches. An early version of the acquisition system timestamped an EEG packet according to the moment at which Python decoded it. This does not accurately represent when the EEG sample was originally acquired. For example, several samples may accumulate temporarily in the serial buffer and then become available to Python at almost the same time. If each of these samples is assigned its decoding time, several consecutive EEG samples receive almost identical timestamps, followed by an artificially large time gap before the next group of samples. The current program avoids assigning an independent host timestamp to every decoded EEG packet. The CHORDS packet decoder instead maintains a continuously increasing **sample index**. The firmware also provides an 8-bit packet counter. By comparing consecutive packet counters, the decoder can detect whether packets were lost; when a missing packet is detected, the sample index is increased accordingly so that the missing time is preserved rather than silently compressing the EEG timeline. 

When Python reads a group of packets from the serial buffer, the program records a single **serial anchor** consisting of the host reception time, the sample index of the newest packet in that batch, the number of packets received and the time since the previous serial read. Consequently, the EEG file contains the ordered sample indices and signal values, while the separate anchor file establishes the relationship between positions in the EEG sample stream and the PsychoPy host clock. This allows individual EEG sample times to be **reconstructed during analysis according to their position in the regularly sampled EEG stream**. The program additionally saves the measured frame intervals and every detected white-to-black or black-to-white stimulus transition. These records make it possible to verify after the experiment that the intended flicker timing was actually generated and to identify unusually long frames or dropped frames. However, these timestamps represent **software/display-flip timing and USB reception timing**. They do not directly measure the physical moment at which the monitor emitted light or the exact moment at which an EEG sample was acquired by the hardware. Unknown display, Arduino and USB transmission latencies may therefore still exist.

## Calibration program for CCA settings

The calibration program evaluates whether the recorded EEG can distinguish between the two SSVEP commands, NEXT and SELECT, using Canonical Correlation Analysis (CCA). This program is fairly simple and straightforward compared to the stimulus generation program. The recorded EEG from the selected occipital channel is first **band-pass filtered between 4 and 30 Hz** using a fourth-order zero-phase Butterworth filter. For each trial, the first **0.25 s after flicker onset is discarded** to avoid the initial visual transient, after which a fixed **3.0 s EEG window** is analysed. For each 3 s EEG window, the program calculates two CCA scores: one for the NEXT stimulus at approximately 10 Hz and one for the SELECT stimulus at approximately 12 Hz. The exact frequencies are calculated separately for each trial from the measured screen refresh rate and the frame-counted flicker periods. For each frequency, synthetic sine and cosine reference signals are generated at the fundamental frequency and its second harmonic. CCA then measures how strongly the recorded EEG follows each of these expected SSVEP patterns, producing a score between 0 and 1 for each target. **Classification is performed by directly comparing the two CCA scores calculated from the same EEG window**. If the NEXT CCA score is larger, the trial is classified as NEXT; if the SELECT score is larger, it is classified as SELECT. Therefore, this implementation does not require additional classifier weights or separate attended and unattended thresholds.

The figure above shows the classification results from one successful two-target SSVEP recording run that achieved 93.1% accuracy, which was considered sufficient to proceed to testing the real-time BCI program. After each calibration run, a summary figure like this is automatically generated for user to evaluate whether the recorded EEG produces sufficiently distinguishable responses to the two target frequencies. **Earlier versions of the classifier used a more complex attention-evidence score, in which CCA values were standardized relative to attended and unattended calibration data. However, this approach produced less reliable classification during testing, so the current implementation uses the simpler direct comparison of CCA scores**. Before a trial is included in the accuracy calculation, the program also checks the quality of the EEG recording, stimulus timing, and EEG–stimulus alignment. Trials containing missing EEG samples, excessive ADC clipping, flat or unusable EEG, unstable display timing, or unreliable timing alignment are marked as invalid. The calibration is considered successful only if at least 30 trials were recorded, at least **90% of all planned trials are correctly classified**, and each target achieves at least **80% correct classification relative to its planned trials**. Finally, the analysis saves the fixed window length, filtering parameters, frequencies, CCA settings, accuracy results, and timing information in `SSVEP_two_target_classifier_config.json`.

## Real-time control of the password selection BCI

The real-time application uses two simultaneously presented SSVEP targets to control numeric password entry: **NEXT** advances the highlighted digit from 0–9, while **SELECT** enters the currently highlighted digit into the password. The two targets flicker at approximately **10 Hz and 12 Hz**, generated using exact frame counting on a 60 Hz display. During each 3.5 s decision epoch, EEG is continuously recorded from the selected occipital channel through the Arduino/CHORDS acquisition system. The signal is aligned with the stimulus timing, band-pass filtered from **4–30 Hz**, and a 3.0 s analysis window is classified using **CCA against sinusoidal reference signals at each stimulus frequency and its second harmonic**. The command with the higher CCA score is executed immediately: NEXT moves the highlighted digit and SELECT adds it to the password. The program also performs real-time quality checks before accepting a decision. Epochs are rejected and repeated if EEG packets are missing, the serial connection is interrupted, stimulus frame timing is unstable, the EEG signal is clipped or nearly flat, or EEG–stimulus timing cannot be aligned reliably. This prevents unreliable recording periods from directly changing the entered password.
